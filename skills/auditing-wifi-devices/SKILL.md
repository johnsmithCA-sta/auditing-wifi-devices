# 局域网设备审计

扫描本地网段 → 识别每台设备 → 与历史台账对比 → 输出只含「变化 + 可疑项」的报告。结果落盘为文件，不把全量输出堆进对话。

## 定位

- **解决什么**：网速突然变慢、路由器里冒出陌生设备、收到异地登录通知——先确认网络里到底有谁。给出可核对的清单 + 每台的判据，不是猜测。
- **凭什么用它**：路由器后台多只给名称与 MAC，看不出类型；只 ping 会漏掉一半设备（手机与 IoT 普遍不回 ICMP）。本技能用 ARP 判活 + 厂商库 + 服务自报 + 端口指纹交叉，并留台账做前后对比。
- **不做什么**：只读——不踢设备、不改配置、不测速。

> 术语：ARP（由 IP 反查网卡 MAC）｜ICMP（ping 协议）｜SSDP（设备广播自身类型的发现协议）｜mDNS（组播 DNS，即 Bonjour）｜OUI（MAC 前三字节的厂商编号）｜DHCP（分配 IP 与主机名的协议）｜U/L 位（MAC 首字节的本地管理位，为 1 即随机地址）。

## 何时用

**用它**：① 网速变慢，想先排除被蹭网；② 路由器里出现不认识的设备；③ 收到账号异地登录通知；④ 建家庭/小办公设备台账、定期巡检；⑤ 核对白名单是否覆盖全部在网设备。

**不用它**：已确认无陌生设备而网速仍慢（走网络故障排查）｜想踢人或改配置（本技能只读）｜信号调优、扩展覆盖｜扫描非自己管理的网络。

## Goal

产出审计报告，须满足：

1. 覆盖网段内所有**当前在网**设备（判据：ARP 表中有真实 MAC，且非组播/广播地址）；
2. 每台给出**判定 + 置信度 + 判据**；
3. 明确列出**新出现 / 消失 / IP 变更**三类变化；
4. 无法定性的设备列入「待确认」并给出下一步手段；
5. **回答「有没有陌生设备在网」的二值结论**（有 / 无 / 待确认），不把判断留给用户。

## Inputs

脚本 `scripts/lan_scan.py`（完整参数见 `--help`）：

| 项 | 默认 |
|---|---|
| 网段 | **自动探测默认路由出口**（换网络/多网卡/VPN 自适应）；探测失败才用 `--subnet` |
| 台账库 | 按网段自动分库 `lan-devices-<网段>.db` |
| 本地 OUI 库 | `--oui-file` 指定；不指定则跳过本地匹配 |
| SSDP 监听 | 30 秒 |
| 端口指纹 | 开启（`--no-ports` 关） |
| 在线厂商查询 | **默认关闭，不发起任何外部请求**；显式加 `--online-vendor` 才发单个 MAC 给公共厂商库 |
| 路由器凭据 | 从本地凭据文件读取，不接受对话中口述（见 Guidelines） |

## Steps

### 0. 开场询问（一次问完）

用一次提问同时取回：**路由器品牌型号**（决定后台路径与是否有现成适配器，不确定则靠 SSDP 自报识别）；**主机名来源**（三选一：写本地凭据文件由脚本读取／用户在已登录浏览器里人工摘录／跳过）；**扫描范围**（本网段 / 连上级网段 / 只看相对上次的变化）。

### 1. 扫描

```bash
python3 scripts/lan_scan.py --out report.md --ssdp-listen 30
```

脚本依次执行：ARP 判活 → SSDP 监听 → mDNS → 端口指纹 → 厂商识别 → 台账差分 → 出报告。判定优先级：**SSDP 自报 > 端口强特征 > OUI 厂商 > 随机 MAC 兜底**。

网段与台账库都自动跟随当前网络，不要写死；也不要让不同网络共用一个台账库，否则差分会把另一网段的设备全报成「新出现」。

### 2. 补齐厂商（脚本默认不联网）

缺本地 OUI 库时大量设备显示「未知」。按序取：① `--oui-file` 指定本地库（首选，不联网）；② 用户同意联网后加 `--online-vendor` 复跑；③ 或用网页抓取工具（WebFetch）访问 `https://api.macvendors.com/<MAC>` 逐个补；④ 回填台账再复跑一次。

### 3. 定性随机 MAC

首字节 U/L 位为 1 即私有/随机地址（iOS、Android、Windows 默认开启），**厂商库查不到属正常，不是可疑信号**。按成本从低到高：

1. **端口指纹**（脚本内置）：如 62078 ⇒ iOS 设备、9100 ⇒ 打印机、554 ⇒ 摄像头、1883 ⇒ MQTT 类 IoT。须与同网已知设备交叉验证该端口是否独有。详见 `references/device-fingerprints.md`。
2. 取路由器 DHCP 客户端列表的**主机名**（最权威）；
3. 引导用户关闭该网络的「私有 Wi-Fi 地址」后重连——真实 MAC 出现即可查厂商，也是让 MAC 白名单稳定的前提。

### 4. 交叉核对并输出

报告与路由器「已连接设备」列表对照：路由器有而扫描没有 → 设备休眠或用了静态 IP，属正常漏报；扫描有而路由器没有 → 可能在上层网关之下（双层 NAT）或用了静态地址。

报告固定六段：概况 → 新出现 → 已消失 → IP 变更 → 在线清单（含判据）→ 待确认。用 `present_files` 展示。

## Examples

**「网速突然变慢，是不是被人蹭网了？」**

1. 先给边界：变慢多数与被蹭无关，但用户要的是明确结论。开场一次问完三件事。
2. 跑 `python3 scripts/lan_scan.py --out report.md`，约 1 分钟出报告。
3. 报告出 8 台在网（**虚构示例**）：网关（SSDP 自报 InternetGatewayDevice）、音箱（自报 MediaRenderer）、两台手机、一台电视、一台打印机，另有两台随机 MAC 待定性。
4. **给二值结论**：全部对得上自家设备 ⇒「没有陌生设备在网，不是被蹭网」，接着查线路与后台更新，**不要改密码**。
5. 待定性那两台要点名并按成本给动作：先看端口指纹（62078 ⇒ iOS），再让用户去后台看 DHCP 主机名。
6. `present_files` 呈现报告。

## Guidelines

- **在网判定以 ARP 为准，不以 ping 为准**。手机、IoT、游戏机普遍不回应 ICMP 但会回应 ARP。判错这条会漏掉一半设备。
- **过滤组播与广播地址**（224.0.0.0–239.255.255.255、网段 .255），否则它们会被当成设备。
- **每台必须带判据**，不允许凭 MAC 前缀猜具体型号。
- **随机 MAC 不得标记为可疑**——隐私特性使然，写明原因并给出定性路径。
- **单次快照不够**。同一时刻 ICMP 常只回约一半在网设备；早/晚/夜各采一轮 → 按 MAC 合并去重得设备全集。也不要凭单轮结果给设备下「生命周期」结论——夜间休眠的常规设备会被误判成短命幽灵设备，进而把人推向不必要的改密码操作。
- **白名单核对要分清「真离线」与「地址轮换」**：随机 MAC 条目长期查不到是预期行为，固定 MAC 条目查不到才是真离线。
- **隐私红线**：设备清单、主机名与 MAC 属个人信息，**清单与主机名不上传、不外发**；查厂商只发单个 MAC，且仅在用户允许在线查询时才发。
- **凭据红线**：**不接受对话中口述的路由器密码**——口述即等于凭据离开本机。只允许两条路径：写入本地凭据文件由脚本读取（如 `~/.workbuddy/keys/<用途>.txt`，权限 600），或用户在已登录浏览器里人工摘录。
- **只读红线**：不踢设备、不改路由器配置、不动白名单。发现可疑设备只报告并给建议，等用户确认后再行动。
- **逃逸条款**：上述规则与用户明确意图冲突时，优先保障用户意图与数据安全，并显式说明偏离了哪一条及原因。

## 常见错误

| 症状 | 原因 | 修复 |
|---|---|---|
| 报告里出现 `224.0.0.251`、`239.255.255.250` | ARP 表混入组播条目 | 脚本已过滤；自行解析 ARP 时务必排除组播与广播段 |
| 绝大多数设备判定「未知」 | 未指定本地 OUI 库 | 先用 `--oui-file`；仍缺的用 WebFetch 查 `api.macvendors.com/<MAC>` |
| ping 只通两三台，怀疑离线 | 设备休眠不回 ICMP | 看 ARP 条目判在线，不以 ping 为准 |
| 同一设备被判成「新设备」 | 启用了随机 MAC 并轮换 | 在设备上关闭该网络的私有 Wi-Fi 地址后重新采集 |

## 依赖

- Python 3.8+，**仅标准库**。
- 可选命令：`fping`（缺失自动降级为 ping，会慢）、`dns-sd`（macOS）、`avahi-browse`（Linux）。
- SSDP 监听 UDP 1900、mDNS 5353，均非特权端口，无需 root。
- **回归自检**：改动 `scripts/` 后跑 `python3 evals/smoke_test.py`，退出码 0 表示核心行为未被破坏。
- 厂商映射、主机名获取路径、各品牌路由器后台入口见 `references/device-fingerprints.md`。
