# auditing-wifi-devices 版本发布说明

> 本文件记录各版本的**显著变更**；版本号遵循语义化版本（X 结构升级 / Y 功能新增 / Z 修复与优化）。

## 0.4.7 版本发布（2026-11-07）

- 修正上一版发布说明里缺失的一处文字（「`--no-ports` 下不据零端口判幽灵」），内容与 0.4.6 相同。

## 0.4.6 版本发布（2026-11-07）

- 修复说明与实际行为不符的问题：没有 `fping` 时只抽样前 254 个地址（非 /24 网段请装 fping 或分段扫）；`--no-ports` 下「零端口」不再是有效判据，别据此判幽灵。
- 优化外部查询的写法：按能力而不是产品名指代网页抓取，换宿主也能照做。
- 优化示例里的设备标识：MAC 统一保留前四段，样例不再带完整地址。

## 0.4.5 版本发布（2026-11-07）

> 写操作现在默认被拒绝：不满足条件就不动。

### 修复

- 修复写操作可能被「顺利执行」的问题：缺少刚刚读到的当前值、没拿到明确确认、设备不在已知范围、回读结果与目标不符，四种情形任一不满足即拒绝并说明原因。
- 修复不认识的设备可能被加进白名单的问题：不显式声明「这是已核实的自用设备」，就不会放行。
- 修复变更记录可能被伪造的问题：手工编造的变更记录不会被当作有效留痕，回读复核只认当次生成的记录。
- 修复含糊答复被当成确认的问题：否定句、「再想想」「行吧行吧」这类回复，以及夹带指令的文本都不算确认。
- 修复正常设备被误判为离线的问题：长期无端口、无自报、无响应的条目单列为「疑似幽灵条目」并附两条外部核对路径，只点名、不判离线。

### 调整

- 调整报告结论：固定给出「有／无／待确认」并附判据与后续动作，不把判断留给使用者。
- 调整自报数据的处理：设备名、服务类型等外部字符串进入报告前清洗，不参与命令拼接。
- 调整允许的写操作范围：只保留上网限时名单增删与 IP-MAC 绑定增删改；改管理员密码 / Wi-Fi 密码 / 加密方式、固件升级、恢复出厂、重启、开 DMZ、改 DHCP 地址池与租期一律拒绝。
- 调整红线范围：隐私、凭据、永不执行清单、不认识的设备不得加白名单，不因任何理由放宽。

## 0.4.0 版本发布（2026-11-07）

- 新增路由器后台接管：在用户已登录的浏览器里读 DHCP 客户端列表（主机名）、白名单与 IP-MAC 绑定表；用户明确要求时可受控改写名单与绑定。不读取、不代填任何凭据，遇登录框即停手。
- 新增两类受控写：上网限时名单的增删、IP-MAC 绑定的增删改。写入须过三闸——先读后写、逐条确认、改完回读留痕。
- 调整「只读」为「默认只读」：不踢设备、不拉黑、不改密码与固件；改管理员密码 / Wi-Fi 密码 / 加密方式、固件升级、恢复出厂、重启、开 DMZ 仍永不执行。
- 调整白名单规则：不认识的设备不得加进白名单——白名单是放行名单，等于给它夜间通行证。
- 现在可以直接说「把它加进白名单」「给它绑个固定 IP」。

## 0.3.0 版本发布（2026-11-07）

- 新增路由器发现补强：监听窗口内主动查询，只在被查询时应答的设备也能被发现——只被动监听会成批漏掉这类设备。
- 优化判据时效性：换了主人的 IP 不再沿用上一轮的判定，不会把新设备认成旧设备。
- 优化设备名核对：可用 mDNS 自报名把「设备名 ↔ IP ↔ MAC」三元绑死；部分第三方投屏器为兼容 AirPlay 会沿用 `model=AppleTV2,1` 标识，不能据此判成 Apple 设备。
- 优化端口判据：开放端口＝有服务，对端拒绝＝设备在线，无应答＝这次没回；最后一种不能用于判活或判无。
- 优化随机 MAC 判读：地址轮换会连带抢 IP、打断静态绑定、掉出家长控制白名单（表现为「每到点就断网」）。
- 优化路由器核对：「IP与MAC绑定」只是静态 ARP、不等于保留 IP；核对家长控制时先分清白名单还是黑名单模式。
- 修复设备明明已离线却长期留在在线清单的问题：这类条目现在单列为「疑似幽灵条目」，并给出两条外部核对路径。
- 调整幽灵条目识别：不再用「ICMP 全丢 + 端口全超时」判离线（休眠设备与代答条目同构，会成批误标），改为只点名、交路由器后台与本机历史 MAC 比对。

## 0.2.0 版本发布（2026-10-12）

### 新增

- 新增一键获取厂商库：运行 `python3 scripts/fetch_oui.py` 下载 Wireshark 厂商注册表到本机缓存，之后扫描自动使用；`--ieee` 追加 IEEE 官方三表，`--check` 查看现有库状态。
- 新增厂商库多文件支持：`--oui-file` 可重复传入多个库文件，三种常见库格式自动识别。

### 优化

- 优化厂商识别覆盖面：新分配在 28/36 位前缀上的设备，现在也能定到厂商。
- 优化多 IP 设备的呈现：同一设备有多个 IP 时按最低 IP 归档，其余 IP 在报告备注，不再被当成多台设备。

### 修复

- 修复首次扫描厂商全为空：不带厂商库时所有真实 MAC 都无法定厂商；现在首次使用按提示运行 `fetch_oui.py` 即可。
- 修复扫描在最后一步崩溃：同一网卡同时有路由地址与链路本地地址（169.254 段）时，写台账会报错退出、整个扫描作废；现在链路本地地址不再计入设备。
- 修复 SSDP 自报设备从报告里消失：对 SSDP 有自报但没进 ARP 表的设备（休眠、静态 IP、上层 NAT 之后），现在列入「待确认」并说明原因。
- 修复缩小扫描范围无效：显式指定子网时，不再混入其他网段的设备。
- 修复报告显示 0 台设备但网络明显有设备：macOS 上解析 ARP 表会因域名解析不可达而无限等待，导致判活被拖空；现在跳过域名解析，并在判活为 0 时给出明确提示。
- 修复网段参数打错时报错难懂：`--subnet` 传入非法值现在给出明确提示并以退出码 2 结束，不再抛异常栈。
- 修复查看库状态顺带建目录：`fetch_oui.py --check` 变为纯只读，不再创建目标目录。
- 修复中断下载留残留文件：下载过程中按 Ctrl-C，不再留下未完成的临时文件。

### 调整

- 调整 mDNS 浏览：目前仅 macOS 支持，其他系统会明确提示跳过，不再静默无结果。

## 0.1.1 版本发布（2026-10-11）

- 新增端口指纹：可凭设备开放的专有端口定性设备类型，对随机 MAC 设备尤其有效（例如开放 62078 即指向 iOS 设备）；默认只探一组精选端口，几秒完成。
- 网段自动跟随网络环境：换 WiFi、换路由器、多网卡或挂 VPN 都不必改参数，只有探测失败时才需手动指定。
- 台账按网段分库：不同网络的设备各存一份，不会再把另一网段的设备误报成「新出现」。
- 在线厂商查询默认关闭：默认只用本地 OUI 库，全程不联网；确需在线查询要显式开启，且只发送单个 MAC。
- 报告内容统一转义：设备自报的名称、服务类型等一律做清洗，避免异常字符破坏报告结构。

## 0.1.0 版本发布（2026-10-10）

- 首个版本：扫描局域网内存活主机，用 ARP 判活、MAC 厂商、SSDP/mDNS 服务自报与端口指纹识别每台设备，建立台账做前后差分，输出以变化与可疑项为主的审计报告。
